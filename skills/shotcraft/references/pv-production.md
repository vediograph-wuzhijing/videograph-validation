# PV制作：先看画面，再写代码

用于参考研究、混合媒介PV和大工程迭代；不替代MCP契约、导演版本保护或人的接受。工具参数以当前服务与`docs/MCP-GUIDE.md`为准。

## 开工：参考画面与已有工具

先读取shotcraft总览，再用`effect_search`分别检索后期与转场，`scene_component_search/get`检索相机、环境、文字与图层。记录选中的组件/效果ID及未覆盖的需求，再决定要新写什么。HTTP备用CLI同样能调用这些工具；连接失败时报告阻塞，不能把未检索说成没有能力。

用户给了参考片时，先抽帧出带绝对时间的联系表，观察至少一个运动片段和关键切点，再读对应代码。只有参考仓库时，在独立临时副本按它实际支持的渲染命令出图，不修改只读参考仓库。记录主体、构图、运动起落、文字层级及镜头接力；不要只凭文档推断画面，也不要复制参考歌词与人物素材。缺少可运行环境或无权使用素材时，说明哪些参考未实际看到，不伪造画面结论。

## 每轮：少量静帧、连续帧、直接读意见

每轮开始与提交前读`project_feedback_inbox({projectId,status:"open"})`；针对单镜可加`shotId`。以返回的目标ID、anchor和preserve为准，不能让人再次口述镜头号。pending意见逐条回应，needs-clarification等待回复，responded等待人比较采用；AI不接受意见或解锁。

未提交源码先走`project_draft_check`，再用`project_draft_stills`取少量关键帧或`project_draft_preview`播放，满意后才正式提交。只重提交改过的镜头；同一共享源码用`project_scene_module_submit`一次提交完整绑定，遵守版本、锁和导演claim，不能用单镜提交循环制造几十份快照。

**改过运动、运镜或转场后，连续帧自查是默认步骤。** 每镜的`project_filmstrip({projectId,shotId})`可直接得到均匀采样的网格并作为导演证据；非硬切转场用`transitionId`。对最容易出问题的约2秒额外取约12帧：

```json
{"projectId":"<工程ID>","start":12,"end":14,"sampleFps":6,"columns":6,"thumbWidth":320,"waitSeconds":25,"embedImages":true}
```

12/14只是参数示例，实际start/end从镜头或事件的歌曲绝对秒数推导，裁到曲长内，不改歌词时间。显式范围诊断不要同时传shotId/transitionId，它们会优先决定时间窗。每次最多24格；关键命中可另用`around:<拍点秒数>,frames:8`得到前后相邻帧，frames表示每侧数量，采样步长为工程帧率。任务未完成则用`project_job_get`续取，读取返回的实际times和图片，不能把“已入队”当作已看运动。

逐格看准备、加速、落点、停留、相邻构图及文字进退；转场查黑帧、闪帧、叠字和下一句歌词提前暴露。局部范围诊断不替代导演要求的每镜/转场证据。只有运动疑点或节奏改动再追加局部`project_rhythm_report`；复用版本仍匹配的证据，不每轮重复全片任务。

连续帧只能发现采样到的变化，不能证明帧间无异常或听感正确。看不到实际播放、听不到音频时明确保留这些限制；用预览与人的观看/聆听补足，不能声称音画与运动已完全接受。

## 2D插画与3D空间

在插画混合PV中，默认把插画作为印刷图版，与3D镜头硬切；确需放入3D空间时优先中远景，避免近景暴露平面感。不加装饰相框；遮罩开洞避开人物身体和脸部。人物、环境和文字分层，水下折射等只作用于环境层，文字保持可读。其他风格或用户明确指定的设计按其意图处理，这些经验不是所有影片的统一美术规则。

## 环境基础件与参数

先`scene_component_get`读取代码、usage、importPath和license，新歌工程已有组件，旧工程按返回的兼容说明处理，不覆盖旧冻结引擎。

| 标准件 | 使用重点 |
|---|---|
| world | position/target、fov、drift/speed；projectWorld用于世界到画布投影；worldCard纹理由调用者管理 |
| environment | sky/ocean/underwater；top/bottom颜色、strength 0..4、speed与seed；用绝对时间驱动，不是物理海洋模拟 |
| layers | 环境/人物/文字分别绘制，选择性后期；释放RenderTarget，遵守材质所有权 |
| text-motion | enter/exit、duration/stagger/distance；先按字素拆分，不更改原歌词起止 |

组件为本项目GPL-3.0-only代码，底层引擎MIT；以组件返回值与许可证为准。引用外部环境代码要记录出处和许可。月相可作为单镜遮罩参数组合，当前不是单独的标准组件，不把自写实现说成库已有能力。

## 按歌词语义选择文字PV配方

一个主语义配一个主动作，先保证唱词和可读性，再加装饰；配方是场景组合建议，非现成特效ID。

| 歌词语义 | 画面配方 | 自查 |
|---|---|---|
| 生成、选择、概率 | 逐token色块，以词/音节真实起点入场 | 未唱词不提前高亮；色块不压字 |
| 犹豫、随机、搜寻 | 采样跳字，最后落定真实歌词 | 跳字是短暂候选，歌词有足够停留 |
| 否定、纠错、舍弃 | 划掉的候选，实际唱词保持主层级 | 不把候选当成歌词或修改其数据 |
| 联系、回忆、依赖 | 注意力连线，在关键词间短暂连接 | 避开正文，连接有语义，不满屏线 |
| 中断、遗忘、重来 | 截断与退格，按字素删除 | 留足读完时间，不切坏合字/组合字符 |

用`text-motion`负责基本进退场，时间从真实歌词/节拍推导；未覆盖的配方组合写在镜头中，先草稿检查与连续帧验证，再考虑是否值得复用。

## 外部MIDI/歌词与歌曲对拍

这里只建立歌曲真值与画面时序，不扩展冻结的OpenUtau模块。读取音频时长、MIDI的PPQ/tempo map和歌词来源；显式选择主旋律，不能把多轨/和弦当成一条旋律。tick先按tempo map积分成绝对秒，再通过音频实测起音与人工确认确定全局偏移；如有局部速度漂移，保留锚点分段映射，不能用一个偏移冒充完整对齐。

日语先按读音划分音节/字素：促音和合并音需要显式标记其所属音符与实际持续时间，长音按真实持续保留，不靠缩短歌词绕过切点校验；不猜汉字读音或声库音素。已有冻结导入入口只用于其支持范围内的草稿核对，不推进新的音素化能力。

至少核对开头、中段、结尾及快句的实测人声起音、MIDI起音、字幕强调与拍点；保留score/manual/audio-aligned/estimated来源。把经确认的节拍、段落、歌词truth交给建工程入口，缺失信号不伪称已测。没有聆听或对齐证据时，交给人确认并报告未验证项。

## 导出前：技术事实与未验证项

读最新收件箱，确认修改回应和人的采用状态；看全片联系表，复核每镜/非硬切转场动态证据与全片节奏报告，提交当前签名的自评。报告四类事实：已看静帧、已看连续帧/播放、已听声音、尚无法验证。未验证项写入自评summary或warning issue，需人的判断，不自造接口字段；blocking不得绕过导演和人工闸门。导出后核对时长、帧数、画幅、音轨和解码，不能用技术成功代替人接受成片。
