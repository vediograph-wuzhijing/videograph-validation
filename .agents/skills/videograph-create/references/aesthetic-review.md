# 创作与审片准则

这份准则用于 VideoGraph 全引擎音乐视频。它把仓库 `skills/shotcraft/` 的分镜、媒介、转场技法与 `video-shotcraft` 已验证的可读性、节奏和审片纪律转化为本平台可执行的检查点。选手法时读原技法文档；这里只规定如何决定和验证，不照搬其他片子的颜色或 Remotion 参数。

## 设计时先定五件事

- **主题**：一句话讲清视觉叙事的变化，例如“封闭空间从秩序走向瓦解”，而不是“酷炫科技感”。确定一个贯穿的可辨认物件、动作或视觉母题，并让它在后段发生变化。
- **媒介**：选择与歌曲情绪相符的材料过程（纸的折叠/撕裂、印刷套准、水彩沉积、金属结构、影像光学等）；表现其沉积、形变或光学机制，而非单层滤镜。参考 `skills/shotcraft/references/media-styles.md`，核实引擎能力和素材许可。
- **能量曲线**：先读 `song_cue_sheet`，给 intro/verse/chorus/bridge/outro 或分析得到的段落分配密度、运动量和留白，定位蓄力、爆发与回落。推算拍点/缺失瞬态要注明；高能段的差异来自构图、运动和叙事升级，而非整屏每拍抖动；全画面级闪白/震动应极少使用。
- **排版与色彩**：有限调色板与明确对比，强调色只给语义重音；文字分“必须读”与“纯纹理”，前者在手机宽度缩小后仍可读。中文先查缺字、回退字体、轮廓或合成问题。没有歌词时不能凭空加歌词。
- **镜头接力**：逐镜写“入口状态、主角动作、出口产物、下一镜如何接”。形状、运动方向、声音重音或视线可交接；不是所有边界都需要溶解。参考 `skills/shotcraft/references/transitions.md` 的 handshake 思路。

## 逐镜检查

1. 静音看开头、中点、动作峰值和末尾：主体是谁，第一眼看哪里，情绪/信息是否可读？只靠漂亮纹理或文字换色而无事件发生，应重新设计动作。
2. 动作应有蓄力、加速度、命中和停留；避免长时间匀速漂移。用 `project_filmstrip` 看连续动作，关键重音以 `around` 查看起势与衰减，不把单张漂亮截图当作运动成立。关键画面落定后留足识别时间，不用连续特效淹没内容。长度依音乐语句而定，不机械套用固定 3 秒镜头。
3. 歌词/旁白如上屏，内容必须来自本工程真实数据；词级强调不能领先人声。没有必要做逐词卡拉OK时，可以用歌词作场景事件而非永久字幕，但需保证用户要求的可读信息仍在。
4. 查真实 PNG 的构图、明暗、对比度、字体像素大小、边缘裁切、眩光和噪点；缩成约手机宽度再看一次。技术抽检只代表能渲染，不能代替自己看图。
5. 帧是时间与数据的确定性函数。预览 seek、中途采样、运动模糊子帧与最终导出都应得到一致画面；随机用固定种子。

## 全片检查

- **不重复**：先用 `project_contact_sheet` 横向检查每镜构图、色彩与段落推进；占位镜头不是已完成画面。相邻镜头的形状、构图、纹理和速度有意变化；重复母题要升级含义，不能复用同一镜头模板换词。
- **观感舒适**：整帧的闪白、震动和推镜是重音，不是底色。节奏主要由镜头内的动作、运镜和换景承担；不要为了让节奏报告的“死区/下拍”数字好看而逐拍加全屏冲击。报告出现“持续整帧明暗脉动”提示时应当收敛。
- **有呼吸**：高潮前有积蓄、高潮后有停顿，结尾承接前文而非突然停机。全片任取一段都能分辨主镜头与陪衬。
- **转场有因**：在切点前、中、后抽帧，再看动态；上一镜的出口与下一镜入口相接。查闪帧、黑帧、叠字和提前露出的下一句歌词。硬切若更准确，就保留硬切。
- **声音与节奏**：视觉重音落在分析得到的拍点或真实瞬态；按镜头/段落跑 `project_rhythm_report`，结合 filmstrip 核查偏移、死区、过忙、连续无节拍反应与闪烁。“问题”要定位并修复；“风格提示”需要解释设计意图，不机械把每个下拍命中率拉满。指标与采样不能代替实际观看/聆听；听不到音频时不声称“听感好”，只报告时序和波形证据，交给能听到的人确认。原曲导出后核对音轨与时间线。
- **来源与许可**：记录哪些是引擎/参考素材，哪些是新写镜头、字体与用户歌曲。参考手法可以学习，不直接复用画面冒充原创。

## 验收记录格式

每次审片至少记录：`工程/目标 ID 与版本签名 | 证据任务 ID、时间点或范围 | 观察到的画面/声音事实 | 问题与严重度 | 修改与复验结果`。记录目标 inputRevision/inputToken/codeHash、转场配置和两侧版本，以及导演 action scope、自评 signature/current；签名由服务生成比对，不自造。例如 `镜头 A / 当前 inputRevision 与 codeHash | stills 任务、00:42.3 | 字幕与强光同区、缩到 480px 无法辨认 | blocking | 降低局部高光并增大字高；新版本同点截图复查通过`。输入改变后必须针对新版本复验，恢复会话不得沿用旧结论。

通过 `project_review_submit({projectId,expectedProjectRevision,review})` 持久化自评：

- `summary` 写整体判断；`assessments` 的 composition、hierarchy、readability、semantics、rhythm、consistency、originality 七项均用非空观察文本，不写无证据分数。
- `evidence: [{jobId,file?,t?,observation}]` 必须引用本工程**当前版本且已完成**的 stills/filmstrip/contact-sheet/rhythm 任务及其真实 PNG。file 若省略取任务首文件，t 若提供须为真实采样时间或覆盖范围；before-feedback 只能用于对比，不能作为当前候选通过证据。
- 覆盖每镜 stills+filmstrip、每个非硬切转场 filmstrip、全片 contact-sheet+rhythm；分段/局部 rhythm 诊断是补充，不代替 next 要求的全曲任务。先完成全部当前技术验证再提交，签名过期必须重取证据。
- `issues: [{severity,targetId?,t?,detail}]` 必须提供数组，可空；severity 为 blocking/warning/intentional。blocking 阻止导出并要求修复，尽量定位到镜头/转场及时间；风格提示可 intentional，但写清设计意图，不为了导出把真实问题降级。`protect?: string[]` 记录返工保留项。

同一个导演 agent 看真实图、读节奏报告并提交自评，无需第二套模型。标明哪些只是技术通过、哪些已实际看片，哪些仍需人工主观确认；不给无证据的“高级感/电影感”结论。AI 自评、反馈响应与 `project_director_complete` 均不等于人已采用，不允许自行解锁、接受意见或绕过导出闸门。审片 job 的 done 不是 AI 判断通过；review action 需自行 submit，再 complete，不能交给 dispatch 自动作判断。
